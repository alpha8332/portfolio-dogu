Demonstration Support — 톤백 과제의 Replay 요구를 실제 로봇에서 확인할 수 있는 기능으로 구현하고, 뉴로메카 내부 테스트베드에서 고객·그룹장·동료의 검토와 승인까지 연결했습니다.

1. 요구와 시연의 실행 경로

1.1 과제 요구를 실물 검토로 연결한 역할

Replay 기능 요구를 과제 담당자에서 그룹장을 거쳐 전달받아 구현했습니다. 기능이 완성된 뒤에는 뉴로메카 내부 테스트베드에서 실제 로봇 동작을 고객·그룹장·동료에게 보여 주고 검토와 승인을 받았습니다. 제 역할은 개발한 기능을 실행 가능한 장비 상태로 준비하고, 실제 수행을 확인할 수 있도록 연결하는 일이었습니다.

1.2 보여 주는 동작의 실행 주체를 구분

과제의 Replay 시연은 선택한 조작 기록을 실제 로봇으로 다시 실행하는 기능입니다. 그래프가 움직이거나 영상이 재생되는 것만으로 실로봇 Replay가 구현됐다고 보지 않았고, 저장한 episode와 실제 장비가 연결되는 경로를 준비했습니다.

2. 실행 준비와 작업 관찰

2.2 시작 자세 정렬과 본 재생의 경계

로봇의 현재 자세는 저장 episode의 첫 자세와 다를 수 있습니다. 첫 sample부터 바로 따라가게 하면 초기 차이가 갑작스러운 이동으로 이어질 수 있어, 시작 자세로 이동해 안정된 것을 확인한 뒤 기록 시간축을 시작하는 Safe Logic을 연결했습니다.

MiMicX의 Replay는 준비·정렬 중에는 본 재생 cursor를 고정하고, 실제 실행 단계에 들어간 뒤 진행도를 갱신합니다. 시연을 준비할 때도 “명령을 보냈다”, “시작점에 도달했다”, “기록 동작을 수행 중이다”를 같은 상태로 보지 않았습니다.

2.3 Dual NURI에서 확인한 다섯 작업

실제로 Replay를 확인한 작업명
작업실물 검토에서 연결해 본 요소
Straight접기 과정의 양팔 이동과 파지 유지
Circle형상 생성과 이후 자세 전환
Knot교차·재파지·인장과 개폐 타이밍
Ring해당 episode의 양팔·엔드이펙터 동작
Shoveling기록된 작업 동작과 실로봇 실행

Straight, Circle, Knot, Ring, Shoveling을 Dual NURI에서 다시 실행해 동작을 확인하고 관련 영상을 확보했습니다. 작업 이름을 나열하는 것으로 끝내지 않고, 팔 동작과 그리퍼 전환이 함께 이어지는지를 보았습니다. 기업과제 원본 영상은 공개하지 않고 실행 구조와 조작 관점을 설명도로 남깁니다.

2.4 로봇 궤적과 작업물 상태를 함께 관찰

일자 접기에서는 중앙을 잡아 인장하고, 그리퍼 자세를 바꾸어 반 접기와 상단 접기로 이어가는 단계가 중요했습니다. 원형 접기에서는 원형을 만드는 것과 이후 큰 말단 회전이 필요한 접기 구간의 난도가 달랐습니다.

매듭에서는 줄을 교차시키는 것만으로 끝나지 않고, 공간을 만들어 반대쪽 도구를 넣고 줄 끝을 재파지한 뒤 당기는 순서가 필요했습니다. 슬립 매듭의 리본 형성까지 확인한 뒤에는 줄이 더 길면 조작 난도가 낮아질 수 있다는 개선 아이디어도 정리했습니다.

이런 작업에서는 팔의 위치가 비슷하게 움직여도 재료가 같은 상태라는 보장이 없습니다. 그래서 양팔의 이동, 개폐 시점, 실제 접촉과 재파지를 같이 보는 것이 시연 준비의 관찰 기준이 됐습니다.

3. 실물 검증과 문제해결

3.1 좌우 팔과 엔드이펙터의 대응 확인

개발 검증 중에는 기록된 gripper 채널과 실제 좌우 장치를 잘못 대응시키는 문제가 있었습니다. 제어기의 tool index와 저장 파일의 채널 순서를 같은 것으로 생각하면 안 됐습니다. 원래 capture 순서인 [left,right]를 기준으로 읽고, 실제 부착물의 소속과 함께 대응시켜 수정했습니다.

이 경험 이후에는 한쪽 팔의 움직임만 보고 실행이 맞다고 판단할 수 없었습니다. 개폐가 발생한 실제 장치와 이후 팔 동작이 이어지는지를 같은 구간에서 확인하는 것이 중요했습니다. 자세한 채널 해석과 수정은 공통 Replay 개발 문서에서 다룹니다.

3.2 시연 준비로 이어진 개발 검증 사례

개발 과정의 현상·조사·수정
현상구분한 원인실물 확인으로 이어진 조치
초기 이동이 잠깐 움직이고 정지목표 도달 판정뿐 아니라 명령을 유지하는 방식정상 Joint Move의 pulse/hold 의미에 맞춰 초기 정렬 보완
그리퍼 동작 뒤 오른팔이 멈춰 보임개폐 사건과 그 이후 실제 pose·저장 target을 분리stale command 대신 계속 변하는 recorded pose 경로 확인
두 팔이 함께 움직이는 구간의 차이한 팔 구간과 양팔 중첩 구간을 나누어 관찰source/actual을 정렬해 좌우 움직임을 다시 검토

처음 보이는 현상만으로 “그리퍼가 다음 동작을 막는다”고 단정하면 수정 방향이 달라질 수 있었습니다. 실제로는 저장된 오른팔 teleop target이 고정됐지만 measured pose는 계속 변한 구간이 있었습니다. 사건이 일어난 시점과 어떤 값이 입력으로 사용됐는지를 연결해서 확인해야 했습니다.

이 사례들은 기능 개발과 반복 실물 확인 과정의 기록입니다. 이렇게 수정한 기능을 다시 실행해 팔·엔드이펙터·작업물의 동작이 함께 이어지는지 확인한 뒤 시연을 준비했습니다.

3.3 다시 수집한 Actual과 기록을 비교하는 방법

Source는 선택한 원래 episode이고 Actual은 Replay하면서 다시 수집한 기록입니다. Actual 파일에는 Data Collection에서 수집을 시작하고 종료하는 수동 여유 구간이 들어갑니다. 파일 전체 길이가 다르다는 이유만으로 Replay 속도가 틀렸다고 판단할 수 없었습니다.

동작 구간을 정렬한 뒤 좌우 관절·TCP 변화와 그리퍼 전환을 나누어 보았습니다. 이전 실행의 Actual로 수정 효과를 증명하지 않고, 수정 후 다시 실행해 얻은 기록과 물리 동작으로 확인하는 방식이 필요했습니다. 이는 시연에 올릴 기능의 준비 상태를 판단하는 기준이었습니다.

3.4 진행 상태·정지 의도와 실제 운동

UI의 RUNNING은 backend의 실행 상태를 나타내지만 실제 파지나 작업 완료까지 대신 판정하지는 않습니다. 정렬 중인지 본 재생 중인지 구분하고, 양팔과 엔드이펙터가 기대한 구간을 수행하는지 실물에서 확인했습니다.

Pause는 기록 시간축을 멈추는 동작이고 Resume는 중간 위치에서 이어가는 동작이며 Stop은 실행 종료와 정리 경로입니다. 해당 기능은 backend가 명령 전송과 상태를 소유하도록 구현했고, 시연 준비에서도 화면 표시가 실제 실행 제어와 연결되는지 보았습니다.

4. 검토·산출물·Engineering Note

4.1 고객·그룹장·동료의 실물 검토와 승인

요구는 과제 담당자에서 그룹장을 통해 전달됐고, 구현한 결과는 고객·그룹장·동료가 실제 로봇 동작으로 검토했습니다. 저는 기능과 장비를 준비하고, 선택한 기록을 실제로 실행해 요구가 동작으로 구현된 상태를 전달했습니다.

시연은 모두 뉴로메카 내부 테스트베드에서 진행했습니다. 이 경험의 핵심은 과제 요구를 전달받은 뒤 개발·실물 확인·참관 검토까지 연결했다는 데 있습니다. 요구를 전달받은 사람이 구현 결과를 직접 보여 주면서, 화면 상태와 실제 수행 사이의 차이를 설명할 수 있어야 했습니다.

4.3 Engineering Note

개발 중에는 같은 알고리즘을 양팔에 적용했으니 동작도 같을 것이라고 보기 쉬웠습니다. 하지만 오른팔의 저장 target과 실제 pose를 나누어 보자, 코드 흐름이 같아도 입력 데이터의 상태가 달라 동작이 달라질 수 있었습니다. 실물 검증은 코드가 실행되는지를 넘어 어떤 데이터로 어떤 장치를 움직였는지 확인하는 과정이라는 점을 배웠습니다.

또한 결과를 전달하려면 실행 가능한 시작 조건과 관찰 기준까지 준비해야 했습니다. 선택한 기록, 초기 자세, 좌우 도구 대응, 실제 작업물의 상태가 함께 맞아야 다른 사람이 기능을 검토할 수 있었습니다. 이 경험을 통해 시연 준비를 개발 이후의 부수 작업이 아니라 구현한 동작의 의미를 공유하는 과정으로 보게 됐습니다.
