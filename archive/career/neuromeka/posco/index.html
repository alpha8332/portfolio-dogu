1. 과제 개요와 시스템

1.1 과제 개요

양극재 제품 포장에 사용하는 톤백을 양팔 로봇으로 다루기 위한 자동화 과제에 참여했습니다. 비정형 작업물을 조작할 수 있는 환경을 만들고, 조작한 동작을 기록해 실제 로봇에서 다시 확인하는 것이 제 업무의 연결점이었습니다.

비전 테스트베드 구성, 텔레오퍼레이션 데이터 수집, KPI 측정 코드와 시험, Replay 개발·적용, 사용성 평가와 시연 지원을 수행했습니다. 개발과 실험은 뉴로메카 내부 테스트베드에서 진행했으며, 작업 방식과 주요 구성 변경은 그룹장과 협의했습니다.

1.2 물리 시스템과 소프트웨어 경계

NURI 양팔의 각 팔은 6개 관절을 갖고, 말단에는 작업에 따라 그리퍼 또는 Tesollo DG-4F를 사용했습니다. 로봇과 PC 사이에는 목표 명령과 실제 상태가 오가며, 카메라는 별도의 USB 경로로 영상을 전달합니다. 명령 전송, 로봇의 실제 움직임, 영상 수집은 서로 다른 경로이므로 한 경로가 정상이라고 다른 경로까지 확인된 것은 아닙니다.

조작에는 SpaceMouse, Vive 계열 장치, Manus Glove 등을 활용했습니다. Vive의 공간 입력과 글러브의 손 입력은 같은 값이 아니며, 각각 제어할 팔과 핸드에 연결해야 합니다. PIKA를 사용하는 평가 구성도 별도로 다뤘습니다. 기존 장치 연동 기반을 활용했고, 직접 추가한 Vive 기능은 Calibration Start 시점의 컨트롤러 진동 피드백입니다.

비전 구성에서는 말단의 D405와 외부 프레임의 D435IF가 서로 다른 시야를 담당했습니다. 카메라 설치와 USB 연결 시험은 직접 수행했으며, 카메라 배치·포트·해상도·FPS 구성안을 제안하고 그룹장 승인을 받아 적용했습니다.

2. 작업과 실행 흐름

2.1 유연 물체 조작: 파지·장력·재파지

톤백과 줄은 강체처럼 한 번의 위치 지정으로 상태가 정해지지 않습니다. 같은 말단 위치라도 어느 지점을 잡았는지, 두 팔이 어느 방향으로 당기는지, 재료가 이미 어떻게 접혀 있는지에 따라 다음 상태가 달라집니다. 따라서 작업을 로봇 궤적 하나로 바로 옮기기보다 파지점·인장 방향·말단 자세·재파지 순서로 나누어 접근했습니다.

실제 조작에서 나눈 문제와 제약
작업조작을 나눈 기준다음 동작을 제한한 요소
일자 접기중앙 파지 → 인장 → 말단 자세 변경 → 반 접기 → 상단 접기그리퍼가 재료를 잡은 방향과 접는 동안 유지할 장력
원형 접기원형을 만드는 구간과 이후 접는 구간을 분리후속 단계에서 필요한 큰 말단 회전과 양팔 도달 자세
매듭형상 만들기 → 반대편 삽입 → 줄 끝 재파지 → 바깥쪽 인장리본을 만들 공간, 줄 길이와 재파지 가능성

요청한 동작을 NURI 양팔로 그대로 재현하기 어려운 경우, 제가 조작하며 확인한 난점과 가능한 동작을 바탕으로 그룹장과 수행 방식을 조정했습니다. 이는 성공 결과를 포장하기 위한 동작 생략이 아니라, 요청한 작업의 의도를 유지하면서 실제 기구학과 조작성에 맞는 단계로 바꾸는 과정이었습니다. 세부 성공 조건과 버전별 평가는 별도의 실험 기록으로 다룹니다.

2.2 실시간 조작 → 데이터 수집 → Robot Replay

데이터 수집은 장치와 로봇이 움직이는 상태를 저장하는 일이고, Replay는 그 기록을 다시 실행할 수 있는 명령으로 해석하는 일입니다. 저장 파일 안에는 실제 자세와 마지막 명령이 함께 들어 있으므로, 재생하려는 대상이 “명령 이력”인지 “실제 수행한 동작”인지 먼저 정해야 했습니다.

Replay를 실행한 로봇의 움직임은 다시 수집해 source와 actual로 비교했습니다. actual에는 수집 버튼을 누르고 끄는 여유 구간도 들어갑니다. 따라서 파일 전체 길이를 맞추기보다 동작 구간을 정렬하고, 좌우 팔과 그리퍼 이벤트를 나누어 원인을 좁혔습니다.

3.2 KPI 달성 결과

양팔이 같은 움직임을 유지하는지와 Master의 실제 움직임을 Slave가 얼마나 늦게 따라가는지를 나누어 평가했습니다. 과제 문서의 KPI-2·KPI-3은 개발 파일에서 각각 KPI1·KPI2로 부릅니다. 에피소드 유사도인 과제 KPI-1과는 다른 시험입니다.

최종 반복 결과 — 평균과 반복 통과를 구분
평가목표결과판정 범위
양팔 동기 오차 / 과제 KPI-2Sync RMSE ≤ 1.0 mm평균 약 0.880 mm평균 기준 충족, 12/20 trials 통과
Master–Slave 지연 / 과제 KPI-3지연 ≤ 50 mstrial judge 평균 48.969 ms평균 기준 충족, 15/20 trials 통과

지연의 trial judge는 X/Z의 대응 위상 통과 시각 차이 중 최댓값입니다. 그 judge를 20회 평균한 48.969 ms와 모든 trial이 50 ms 이하라는 주장은 다릅니다. 결과 표와 그래프의 시험 회차도 구분해 상세 보고서에 설명합니다.

4.2 Engineering Note

이 과제에서는 각 기능이 따로 동작하는 것보다 서로 다른 경로의 의미를 맞추는 일에 더 많은 판단이 필요했습니다. 카메라가 발견되는 것과 쓸 수 있는 영상이 들어오는 것, 저장된 목표와 실제 움직임, 양팔 동기와 개별 추종을 구분해야 다음 수정의 방향이 보였습니다.

특히 오른팔 문제를 해결하며, 그리퍼 이벤트 뒤에 증상이 나타났다는 이유만으로 그리퍼를 원인으로 고정하면 안 된다는 것을 배웠습니다. 사건이 발생한 시점과 동작을 결정한 데이터 경로를 함께 따라가야, 겉으로 비슷한 정지 현상을 서로 다른 문제로 나눌 수 있었습니다.
