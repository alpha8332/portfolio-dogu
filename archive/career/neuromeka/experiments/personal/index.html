1. 실험 장비와 초기 수집

1.1 누리 양팔·2지 그리퍼와 카메라 구성

개인 실험은 누리 양팔과 2지 그리퍼를 사용했습니다. 초기 Pick & Place에서는 오른팔을 고정해 손목 카메라로 바나나와 트레이를 보게 하고, 왼팔로 집어 트레이에 넣었습니다. 손목 카메라 두 대를 관측으로 사용하면서 물체와 목적지가 영상에 들어오는지 확인했습니다.

1.2 Banana v1 — 배치를 고정한 10회 교시

3월 18일에는 초기 로봇 자세, 바나나 위치·자세, 트레이 위치를 고정하고 Vive로 10회 수집했습니다. 환경 변수를 줄인 상태에서 접근·파지·이동·놓기의 전체 연결을 먼저 살폈습니다. 입력은 왼팔 위치·속도·그리퍼와 손목 영상, 출력은 왼팔 말단 위치·방향·그리퍼와 보조 신호로 구성했습니다.

카메라는 책상 영역을 중심으로 crop했고 relative on/off를 비교했습니다. 실제로 성공한 실행도 있었지만, 성공한 동작에서도 매끄럽지 않은 움직임을 관찰했습니다. 당시 epoch·시간·성공 빈도는 회상 표현이 섞여 있어 정밀한 비교 지표로 쓰기보다 초기 연결 시험으로 남깁니다.

1.3 Banana v2 — 무작위 50회로도 남은 빈 조건

3월 23일에는 트레이와 초기 로봇 자세를 고정하고 바나나의 위치·자세만 임의로 바꾸어 50회 수집했습니다. 수집 후 보니 일부 샘플은 비슷하게 중복됐고, 어떤 위치·자세 조합은 충분히 들어 있지 않았습니다. 작업 영역 안에 바나나를 놓아도 안정적으로 파지하지 못하는 경우가 있었습니다.

v2에서 정리한 입력과 학습 조건
항목해당 실험의 설정
로봇·카메라누리 양팔·2지 그리퍼·손목 카메라 2대
입력왼팔 위치·속도·그리퍼와 양쪽 손목 영상
출력왼팔 말단 위치·방향·그리퍼와 보조 출력
전처리TCP 기준 relative on, 책상 영역 crop
학습 메모약 500 epoch, 10시간 20분, loss 0.0067

수직 방향으로 놓은 바나나, 특히 왼팔에서 먼 위치에서 파지가 어려웠습니다. 수평·수직을 위치별로 나눠 본 관찰을 바탕으로 다음 수집에서는 위치와 방향을 먼저 정하기로 했습니다. 이때 적어 둔 잠정 성공률은 평가 회차가 확정된 결과가 아니므로, 부족한 조건을 찾은 관찰로 해석합니다.

2. 수집 조건 체계화

2.1 Banana v3 — 80개 조건과 추가 반복

3월 25일에는 트레이 위치 4개, 바나나 위치 5개, 바나나 자세 4종(수평·수직·좌측 대각·우측 대각)을 구분했습니다. 기본 조합을 모두 포함하고 어려운 조합에 추가 반복을 배정해 수집표의 수행 횟수를 100회로 정리했습니다.

4×5×4=80;80+20=100기본 조건 수와 추가 반복

트레이 위치도 바뀌므로 바나나만 보아서는 놓을 위치를 정할 수 없습니다. 관측 영상에 물체와 목적지가 함께 보이는지 확인하고, 바나나 중앙을 잡으며 pick/place에서 잠깐 멈춘 뒤 다음 구간으로 넘어갔습니다. 덜컹하거나 멈칫한 교시는 Reject했습니다.

수집표의 100회는 어떤 조건을 얼마나 교시했는지를 나타냅니다. 이 숫자만으로 정책의 최종 성공률을 판단할 수는 없습니다. 학습과 실행을 비교할 때는 해당 데이터 선택, checkpoint와 실행 배치를 연결해 보아야 합니다.

2.2 톤백 배치 — 9개 위치에서 40회 수집

톤백 환경으로 옮긴 3월 26일 기록에서는 트레이를 고정하고 바나나 위치 9개와 자세 4종을 조합했습니다. 기본 36개 조건에 추가 반복 4회를 더해 수행 횟수는 40회였습니다. 공간이 바뀌면서 같은 Pick & Place도 배경·카메라 시야·팔의 접근 방향이 달라졌습니다.

바나나 위치별 수행 횟수
위치123456789합계
횟수54454464440

배치 설명에는 손목 2대와 프레임 상단 2대가 등장하지만 학습 설정은 선택된 손목 영상 2대를 기재합니다. 설치한 카메라 수와 모델이 입력으로 사용한 카메라 수를 같은 것으로 세지 않았습니다. 어떤 시야를 실제 학습에 사용했는지가 중요했습니다.

3. 전달·양팔 작업과 실행 실패

3.1 Handover Pick & Place — 파지의 주체가 바뀌는 순간

오른팔로 바나나를 집어 왼팔에 전달하고, 왼팔이 받아 트레이에 놓는 작업을 다뤘습니다. 단순 Pick & Place와 달리 물체를 지지하는 팔이 도중에 바뀝니다. 접근 위치가 맞아도 받는 팔의 grasp와 주는 팔의 release 순서가 맞지 않으면 물체가 떨어지거나 두 팔 사이에 구속될 수 있습니다.

4월 8일 수집 메모에서는 바나나 중앙을 잡고, 로봇을 천천히 움직이며 pick/place에서 잠깐 정지한 뒤 이동하도록 했습니다. 손목 영상에서 바나나가 가려질 수 있어 해당 시점을 보며 조작하고, 덜컹거리거나 멈칫한 episode는 제외했습니다. 최종 버전별 성공률·영상 평가는 별도 기록으로 이어갑니다.

3.2 Bimanual Object Placement — 서로 다른 작업 순서를 보존

양팔로 물체를 집어 중앙 접시에 놓는 작업을 수행했습니다. 한편 5월 12일 수집 시나리오에는 오른팔로 바나나를 놓고 정위치로 돌아온 뒤, 왼팔로 인형을 놓고 복귀하는 순차 작업이 적혀 있습니다. 두 팔로 인형을 배치한 작업과 이 순차 시나리오는 서로 다른 버전으로 유지합니다.

그리퍼 손가락의 높이를 고려해 바닥보다 약간 위에서 grasp하고, 각각의 영상에서 물체가 계속 보이는지 보았습니다. 동작이 끊긴 episode를 제외하는 기준은 양팔에서도 유지했습니다. 양팔이라는 이유만으로 두 팔의 모든 단계가 동시 실행되는 것은 아니었습니다.

3.3 Loss가 낮아도 바뀐 카메라에서 실패한 이유

후속 양팔 학습 기록에는 양팔 위치·속도·그리퍼, 손목 영상 2대와 중앙 영상 1대를 입력으로 사용하고 absolute·no crop·is_progress를 적용한 설정이 있습니다. ACT Full, batch 16, 최대 1000 epoch 설정과 함께 50 epoch에서 loss 약 0.01을 관찰했습니다.

그런데 실행 때 카메라 각도와 테이블 배치가 달라져 실패를 반복했습니다. 이는 학습 오차가 낮아진 것과 입력 분포가 유지된 것이 다르다는 사례였습니다. 카메라의 시점이 바뀌면 같은 로봇·물체라도 픽셀 위치와 가림 관계가 달라집니다. crop을 쓰지 않았다는 사실만으로 이런 변화를 흡수할 수 있는 것은 아니었습니다.

4. Engineering Note

4.1 Engineering Note

v2에서 무작위로 늘린 데이터와 v3에서 조건을 나눈 데이터를 비교하며, 빠진 상황을 찾을 수 있는 수집표가 다음 실험의 방향을 만든다는 점을 배웠습니다. 특정 위치의 실패를 발견했다면 전체 횟수를 늘리기 전에 그 위치와 자세, 시야와 파지 조건을 나누어 보아야 했습니다.

또한 카메라·물체 배치·교시 속도는 데이터의 부수 정보가 아니었습니다. 실제 rollout이 기대와 다를 때 모델만 다시 학습하기보다, 그 모델이 보았던 조건을 지금의 로봇에 다시 제공하고 있는지부터 확인해야 한다고 생각하게 됐습니다.
