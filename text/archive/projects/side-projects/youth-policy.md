## Problem & Team Workflow

흩어진 정책 정보를 사용자가 찾을 수 있도록 정리하는 팀 프로젝트입니다. 데이터와 팀 리더 역할을 맡아 작업 계획·기록·인계와 통합 기준을 다뤘습니다. Frontend·Backend 전부를 단독 개발한 것은 아닙니다.

## Data Collection, Extraction & Validation

공식 출처의 수집·추출·정규화·검증 흐름을 다루고 지역·연령·기간의 근거를 보존했습니다. 값이 없거나 불확실한 경우를 확정값처럼 통과시키지 않도록 구분했습니다.

## Regional Data Recovery

브라우저 수집 실패와 필드 근거·현재성을 나누어 확인하고 검토 대상과 되돌릴 범위를 제한했습니다.

## Public Dataset & Delivery

공개 가능한 데이터와 개발용 DB의 범위를 나누고 artifact·manifest·hash와 활성 목록이 일치하도록 전달 경로를 다뤘습니다.

## Search & Rule-based Recommendation

규칙 기반 자연어 해석과 지역 계층·분야·추천 이유를 연결했습니다. LLM/RAG와 계정 동기화·외부 push는 완료 기능으로 넣지 않습니다.

## Cross-Team Integration & QA

팀 사이 JSON·DTO·타입·pagination 계약과 제출물을 맞췄습니다. Git 충돌 해결과 실제 API 의미의 불일치는 따로 확인했습니다.

## Persistence & Runtime Reliability

DB의 원자적 저장과 batch rollback, 시간·로그 처리, 문서와 실제 실행의 차이를 확인했습니다. 단일 관찰값을 반복 성능 시험으로 바꾸지 않았습니다.
